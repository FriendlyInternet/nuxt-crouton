Nuxt Crouton is a **modular ecosystem** consisting of a core layer and multiple feature packages. Every package is a Nuxt layer you switch on by adding it to `extends`, keeping bundle sizes small while allowing you to use only what you need.

::callout{icon="i-lucide-info" color="blue"}
**Core bundles the essentials:** Extending `@fyit/crouton-core` automatically includes the **auth**, **admin**, and **i18n** features. Optional features are enabled by installing their package and adding it to `extends`.
::

## Architecture Overview

```
@fyit/crouton-core (base CRUD layer — every app extends it)
│
├── Bundled (extended by core, never listed separately):
│   ├── @fyit/crouton-auth (authentication)
│   ├── @fyit/crouton-admin (admin dashboard)
│   └── @fyit/crouton-i18n (translations)
│
├── Optional add-ons (extend the ones you need):
│   ├── @fyit/crouton-editor (TipTap)
│   ├── @fyit/crouton-flow (Vue Flow)
│   ├── @fyit/crouton-three (TresJS / Three.js)
│   ├── @fyit/crouton-assets (media library)
│   ├── @fyit/crouton-maps (MapLibre)
│   ├── @fyit/crouton-ai (LLM integration)
│   ├── @fyit/crouton-email (Vue Email)
│   ├── @fyit/crouton-events (audit trail)
│   ├── @fyit/crouton-collab (real-time)
│   ├── @fyit/crouton-pages (CMS)
│   ├── @fyit/crouton-devtools (dev tools)
│   ├── @fyit/crouton-feedback (in-page feedback toolkit)
│   └── @fyit/crouton-themes (UI themes)
│
└── Mini-apps (experimental):
    ├── @fyit/crouton-bookings
    └── @fyit/crouton-sales
```

## Core Packages (Auto-Included)

`@fyit/crouton-core` is the one layer every app extends. It extends `@fyit/crouton-auth`, `@fyit/crouton-admin` and `@fyit/crouton-i18n` itself, so those need no separate installation or `extends` entry.

### @fyit/crouton-core

**Purpose**: Base CRUD layer with collections, composables, and components
**Install**: `pnpm add @fyit/crouton-core`, then `extends: ['@fyit/crouton-core']`
**Status**: Always extended — the entry point of every Crouton app

**Contains**:
- Composables (useCollectionQuery, useCollectionMutation, useCrouton, useCroutonApps)
- Base components (CroutonCollection, CroutonFormActionButton, CroutonForm)
- Container management (slideover, modal, dialog, inline)
- Cache invalidation system
- App auto-discovery system
- TypeScript types

---

### @fyit/crouton-auth

**Purpose**: Authentication layer with teams, passkeys, and 2FA
**Status**: Bundled by `@fyit/crouton-core`

**Contains**:
- Better Auth integration
- Team/organization management (multi-tenant, single-tenant, personal modes)
- Passkey/WebAuthn support
- Two-factor authentication (TOTP)
- OAuth providers (Google, GitHub, etc.)
- Auth composables (useAuth, useSession, useTeam)
- Pre-built auth components

**Routes provided**: `/auth/*` (login, register, forgot-password, etc.)

---

### @fyit/crouton-admin

**Purpose**: Super admin dashboard for system-wide management
**Status**: Bundled by `@fyit/crouton-core`

**Contains**:
- Super admin dashboard with stats
- User management (list, create, ban, unban, delete)
- Team oversight (view all teams/members)
- User impersonation (debug as any user)
- Super admin middleware

**Routes provided**: `/super-admin/*`

---

### @fyit/crouton-i18n

**Purpose**: Translation and multi-language support
**Status**: Bundled by `@fyit/crouton-core`

**Contains**:
- CroutonI18nInput component
- LanguageSwitcher component
- DevModeToggle component
- useEntityTranslations composable
- useT composable for translations
- Database-backed team overrides

**Provides**:
- `common.*` - Generic UI strings
- `forms.*` - Form field labels
- `errors.*` - Error messages
- `time.*` - Time formatting strings
- `navigation.*` - Navigation labels

Install the package and add it to `extends` as needed (`crouton add <module>` does both steps for you).

**Contains**:
- EditorSimple component (WYSIWYG editor)
- EditorToolbar component
- Tiptap integration
- Pre-configured extensions

### @fyit/crouton-ai

**Purpose**: AI chat and completion integration
**Enable**: `extends: ['@fyit/crouton-ai']`

- useAIProvider() composable (provider/model configuration)

**Environment Variables**:

```bash
NUXT_ANTHROPIC_API_KEY=sk-ant-...
```

- NuxtHub blob storage integration

**Requires**: `hub: { blob: true }` in nuxt.config

### @fyit/crouton-three

**Purpose**: 3D rendering with TresJS (Three.js for Vue) — interactive scenes, model viewer, and games
**Extend**: `extends: ['@fyit/crouton-core', '@fyit/crouton-three']`

**Contains**:
- `CroutonThreeScene` — flexible canvas wrapper (camera, lights, orbit controls, slot for any 3D content)
- `CroutonThreeModelViewer` — glTF/.glb model viewer with auto-rotate
- `CroutonThreeStarterScene` — runnable WASD/arrow-key game starter
- `useThreeControls()` — keyboard movement composable
- **3D Model** page block for crouton-pages (with i18n + crouton-assets model picker)

---

### @fyit/crouton-email

**Purpose**: Email infrastructure with Vue Email templates and Resend
**Enable**: `extends: ['@fyit/crouton-email']`

**Contains**:
- useEmailService() composable
- Convenience senders (sendVerificationEmail, sendMagicLink, etc.)
- Vue Email templates
- Client flow components (EmailVerificationFlow, MagicLinkSent)
- Resend integration

**Environment Variables**:
```bash
RESEND_API_KEY=re_xxx
```

**Integration**: Works with `@fyit/crouton-auth` for auth emails

---

### @fyit/crouton-collab

**Purpose**: Real-time collaboration with Yjs CRDTs
**Enable**: `extends: ['@fyit/crouton-collab']`

**Contains**:
- Cloudflare Durable Objects for Yjs sync
- useCollabConnection, useCollabSync, useCollabPresence composables
- useCollabEditor for TipTap integration
- CollabStatus, CollabPresence, CollabCursors components
- Presence tracking and cursor sharing

**Room types**: page (TipTap), flow (graphs), document (text), generic

**Note**: Sync mode requires Cloudflare Durable Objects

---

### @fyit/crouton-pages

**Purpose**: CMS-like page management system
**Enable**: `extends: ['@fyit/crouton-pages']`

**Contains**:
- Page types from app packages
- Tree/sortable layout for page ordering
- Public page rendering at `/[team]/[slug]`
- Block-based page editor
- Custom domain support with automatic team resolution
- usePageTypes, useDomainContext, useNavigation composables

**URL Structure**:
- Public pages: `/[team]/[slug]`
- Admin: `/admin/[team]/pages`

---

### @fyit/crouton-devtools

**Purpose**: Development tools and debugging utilities
**Enable**: `modules: ['@fyit/crouton-devtools']` (a Nuxt module, not a layer)

**Contains**:
- Debug panel for inspecting collections
- API explorer for testing endpoints
- Schema viewer for collection schemas
- Development helpers

**Note**: Only active in development mode (`nuxt dev`); no impact on production builds

---

### @fyit/crouton-feedback

**Purpose**: A drop-in in-page feedback toolkit for any Nuxt + Nuxt UI 4 app (no crouton-core required)
**Install**: `modules: ['@nuxt/ui', '@fyit/crouton-feedback']`

**Contains**:
- A bottom-right **glasses launcher** with toggleable tools
- **Console** — eruda, a mobile in-page devtools console (lazy-loaded)
- **Annotate** — pin a comment on any element; resolves the owning source file
- A pluggable **feedback sink**: `webhook` · `slack` · `discord` · `github` (issue/PR comment)

**Configure**: pick the destination via `croutonFeedback.feedback.sink` or the `NUXT_CROUTON_FEEDBACK_*` env vars (credentials stay server-side). `@fyit/crouton-devtools` installs this automatically under its own gate, so `crouton init` apps get it with zero wiring.

---

### @fyit/crouton-themes

**Purpose**: Swappable UI themes for Nuxt UI applications
**Enable**: extend a theme directly (see below)

**Available Themes**:

| Theme | Description | Extend Path |
|-------|-------------|-------------|
| KO | Hardware-inspired (Teenage Engineering KO II) | `@fyit/crouton-themes/ko` |

**Usage** (theme-specific extend):
```typescript

  extends: ['@fyit/crouton-themes/ko']
})
```

**Contains**:
- Design tokens (CSS custom properties)
- Nuxt UI component variant overrides (`variant="ko"`)
- Theme-specific components (KoLed, KoKnob, KoPanel)

## Development Tools (Not Runtime)

These packages are used during development and are not included in your production bundle.

### @fyit/crouton-cli

**Purpose**: CLI tool for code generation
**Install**: `pnpm add -D @fyit/crouton-cli`

**Commands**:
```bash
crouton generate <layer> <collection>
crouton rollback <layer> <collection>
crouton rollback-bulk --layer=<name>
crouton rollback-interactive
crouton init
crouton install
```

**Key insight**: Dev-time dependency only. Generated code doesn't depend on it.

---

**Contains**:
- Schema design tools

- Collection/layer scanning

**Tools**: `design_schema`, `validate_schema`, `generate_collection`, `list_collections`, `dry_run`, `rollback`

## Installation Patterns

### Standard Setup (Recommended)

```bash
# Install the core layer
pnpm add @fyit/crouton-core

# Install CLI for code generation (dev dependency)
pnpm add -D @fyit/crouton-cli
```

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  extends: ['@fyit/crouton-core']
  // Gets: auth, admin, i18n automatically
})
```

### Enable Optional Features

Install the package, then add it to `extends` (`crouton add <module>` does both):

```bash
pnpm add @fyit/crouton-editor @fyit/crouton-assets @fyit/crouton-events @fyit/crouton-pages
```

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  extends: [
    '@fyit/crouton-core',
    // Features you need
    '@fyit/crouton-editor',
    '@fyit/crouton-assets',
    '@fyit/crouton-events',
    '@fyit/crouton-pages'
  ]
})
```

### Full-Featured App

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  extends: [
    '@fyit/crouton-core',
    // All optional features
    '@fyit/crouton-editor',
    '@fyit/crouton-flow',
    '@fyit/crouton-assets',
```

## Three-Tier Route Architecture

| Tier | Route Pattern | Purpose | Access |
|------|---------------|---------|--------|
| **User** | `/dashboard/[team]/*` | User-facing features | Any team member |
| **Admin** | `/admin/[team]/*` | Team management | Team admins/owners |
| **Super Admin** | `/super-admin/*` | System management | App owner only |

## Field Types and Required Packages

When defining collection schemas, certain field types require specific packages to be extended.

| Field Type | Required Feature | Config |
|------------|------------------|--------|
| `editor` | Editor | `extends: ['@fyit/crouton-editor']` |
| `i18n` / `translation` | i18n | bundled by `@fyit/crouton-core` |
| `asset` | Assets | `extends: ['@fyit/crouton-assets']` |
| `map` / `location` | Maps | `extends: ['@fyit/crouton-maps']` |
| `flow` | Flow | `extends: ['@fyit/crouton-flow']` |

## Why This Architecture?

### Benefits

**1. Small Bundle Sizes**
- Only include what you need
- Packages you don't extend aren't in the build
- No unused code in production

**2. Independent Updates**
- Core can be updated without breaking add-ons
- Add-ons can evolve independently
- Generator improvements don't require core updates

**3. Clear Separation**
- Generated code vs runtime code
- Core features vs optional add-ons
- Development tools vs production dependencies

**4. Flexible Adoption**
- Start simple, add complexity as needed
- Drop packages you're not using from `extends`
- Mix and match capabilities

### Design Decisions

**Q: Why is the generator a separate package?**
A: It's a dev-time tool. Your production app doesn't need the generator, templates, or CLI code.

**Q: Why `extends` instead of a module with feature flags?**
A: A package is switched on by extending it, so the `extends` array is the single source of truth for what's in your app. The `features` block in `crouton.config.js` only carries a package's prompted configuration — it never switches a package on or off.

**Q: Do add-ons depend on each other?**
A: Mostly no. Each add-on depends on core. Some have optional integrations (e.g., email + auth).

## Troubleshooting

### "Module not found: @fyit/crouton-core"

The core package isn't installed:
```bash
pnpm add @fyit/crouton-core
```

### "crouton-generate command not found"

The generator isn't installed:
```bash
pnpm add -D @fyit/crouton-cli
```

### Feature component not found

Make sure the feature's package is installed and extended:
```typescript
extends: ['@fyit/crouton-core', '@fyit/crouton-editor']  // Extend the feature's package
```

### TypeScript errors after enabling feature

Run Nuxt prepare to regenerate types:
```bash
npx nuxt prepare
npx nuxt typecheck
```
