A Crouton app has two halves.

| | Generated code | Core layer |
| --- | --- | --- |
| Where | `layers/<layer>/collections/<collection>/` in your repo | `@fyit/crouton-core` in `node_modules` |
| Who writes it | `crouton config` / `crouton generate`, once per collection | the package |
| Who changes it | you | a package update |
| What's in it | the form, the list, columns + validation, API routes, Drizzle table and queries, types | the form container, `<CroutonCollection>`, data composables, the admin screens, auth, teams, translations |

The generated files are ordinary source files that use the core layer. The core layer knows nothing about your collections except what the registry tells it (`croutonCollections`, see [Collections and layers](/fundamentals/collections#the-registry)).

## What the core layer brings

Your app's `nuxt.config.ts` extends `@fyit/crouton-core`. Core in turn extends three more layers, so you get them without installing them separately:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    '@fyit/crouton-core',   // also brings crouton-i18n, crouton-auth, crouton-admin
    './layers/shop'         // added by the generator
  ]
})
```

- **`@fyit/crouton-auth`**: sign-in, teams and roles. It also provides `resolveTeamAndCheckMembership`, which every generated route calls.
- **`@fyit/crouton-admin`**: the super-admin area.
- **`@fyit/crouton-i18n`**: translated fields and UI strings.

Core itself holds the parts every collection shares:

- **Data:** `useCollectionQuery`, `useCollectionItem`, `useCollectionMutation`, `useCroutonMutate` ([Data operations](/fundamentals/data-operations))
- **Forms:** `useCrouton()` opens a form in a slide-over, modal, dialog or inline panel. The app shell (`app.vue`) already mounts the container.
- **Lists:** `<CroutonCollection>` renders rows as a table, list, grid, tree or kanban board.
- **Screens:** `/admin/<team>/crouton/<collectionKey>` shows any registered collection.

Optional packages, such as rich text, file uploads or maps, are separate layers you add with `crouton add`. See [Installation](/getting-started/installation#add-optional-packages).

## One request, end to end

What happens when the products list loads, and when someone saves the form:

```
ShopProductsList (List.vue, generated)
  └─ useCollectionQuery('shopProducts')                  core
       ├─ looks up shopProducts in croutonCollections → apiPath 'shop-products'
       └─ GET /api/teams/<teamId>/shop-products
            └─ index.get.ts                              generated
                 ├─ resolveTeamAndCheckMembership(event)  crouton-auth
                 └─ getAllShopProducts(team.id)           generated queries.ts → Drizzle → shop_products

ShopProductsForm (_Form.vue, generated) — save
  └─ useCollectionMutation('shopProducts').create(data)  core
       ├─ POST /api/teams/<teamId>/shop-products
       │    └─ index.post.ts: membership check, Zod validation, sets teamId/owner/createdBy/updatedBy
       ├─ fires the 'crouton:mutation' hook (crouton-events listens to it)
       └─ refreshes every cached shopProducts query, so the list updates
```

The team id comes from the current route or session, through core's `useTeamContext`. Until it is known, for example during server rendering before auth has loaded, a query sends no request and returns an empty list. It fetches as soon as the team is known. Routes under `/super-admin/` call `/api/super-admin/<apiPath>` instead of the team routes.

## Why it is split this way

- **You can read and change everything that is specific to your data.** The form, the columns, the validation and the SQL are files in your repo, not configuration that a runtime interprets.
- **Shared behaviour is updated in one place.** A fix to the form container, the cache refresh or the auth check reaches every collection with a package update, without regenerating.
- **Regenerating does not overwrite your changes by default.** It skips files that already exist unless you pass `--force`. See [Generated code](/fundamentals/generated-code#regenerating).
