::callout{icon="i-lucide-triangle-alert" color="red"}
**Nuxt 4 and Nuxt UI 4 only.** Crouton's layers use Nuxt 4's `app/` folder layout; on Nuxt 3 their pages and components are not found. See [Troubleshooting](/guides/troubleshooting#layer-pages-404-errors).
::

There are two ways in. Pick one.

## Option A — new app with `crouton init`

`crouton init` creates the app folder, generates any collections already listed in its config, writes the database migrations, and checks the result.

```bash
npx crouton init my-app
```

What it writes (in `apps/my-app/` by default; `--out <dir>` puts it elsewhere, `--poc` puts it in `pocs/my-app/`):

| File | What it is |
| --- | --- |
| `nuxt.config.ts` | extends `@fyit/crouton-core` (plus any `--features`), `hub: { db: 'sqlite', kv: true }` |
| `crouton.config.js` | the generator's config — empty `collections` and `targets`, `dialect: 'sqlite'` |
| `schemas/` | where your collection field files go |
| `app/assets/css/main.css` | Tailwind + Nuxt UI, and the `@source` line that styles the layers |
| `app/app.config.ts` | the collection registry (`croutonCollections`) |
| `server/db/schema.ts` | database schema exports (auth tables to start) |
| `.env` | `BETTER_AUTH_SECRET` (a fresh random value) and `BETTER_AUTH_URL` |
| `wrangler.jsonc`, `deploy.config.json`, `scripts/` | Cloudflare Workers deploy setup — leave out with `--noCf` (write it in camelCase: `--no-cf` is ignored today, [#3997](https://github.com/FriendlyInternet/nuxt-crouton/issues/3997)) |

It also adds the layout package (`@fyit/crouton-layout`) by default; `--no-layout` leaves it out. Add packages up front with `--features`, e.g. `--features editor,assets`.

Then:

```bash
cd apps/my-app
pnpm install
pnpm dev
```

::callout{icon="i-lucide-info"}
**Inside vs outside this monorepo.** `crouton init` writes `workspace:*` versions for the `@fyit/*` packages in `package.json`, because it is built for the Crouton monorepo. In your own repo, change those to real versions (e.g. `^0.1.0`) before `pnpm install`.
::

`npx crouton init my-app --dry-run` lists the files without writing anything. All flags: [CLI reference](/api-reference/cli#init).

## Option B — add Crouton to an existing Nuxt 4 app

### Install

```bash
pnpm add @fyit/crouton-core
pnpm add -D @fyit/crouton-cli
```

### Extend the core layer

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@fyit/crouton-core'],
  css: ['~/assets/css/main.css'],
  hub: { db: 'sqlite' }
})
```

`@fyit/crouton-core` already extends auth, admin and translations, and registers `@nuxthub/core`, `@nuxt/ui`, `@vueuse/nuxt`, `@nuxt/image` and `@nuxtjs/seo`. Do not list any of those again in your own `extends` or `modules`.

::callout{icon="i-lucide-triangle-alert" color="amber"}
**`hub: { db: 'sqlite' }`, not `hub: { database: true }`.** The old key fails the build with *Cannot resolve entry module .nuxt/hub/db/schema.entry.ts*. With `db: 'sqlite'`, NuxtHub applies all layers' migrations when the dev server starts. File storage (`hub.blob`) is switched on by core for you.
::

### Configure Tailwind CSS

Tailwind CSS 4 does not scan packages in `node_modules`, so classes used only inside Crouton's components (hover states, colours) go missing unless you point it at them:

```css [app/assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";

/* Scan Nuxt Crouton layers for Tailwind classes */
@source "../../../node_modules/@fyit/crouton*/app/**/*.{vue,js,ts}";
```

The `@source` path is relative to the CSS file — count one `../` per folder between the CSS file and the folder that holds `node_modules`. You can skip this step: the first `crouton generate` run finds your CSS file (`app/assets/css/main.css`, `app/assets/css/tailwind.css`, `app.css`, …) and adds the line if it is missing.

### Set the auth secret

```bash [.env]
BETTER_AUTH_SECRET=<a long random string>
BETTER_AUTH_URL=http://localhost:3000
```

Without `BETTER_AUTH_SECRET` the server logs a warning at start and sign-in is not safe for production. Social sign-in is optional and is switched on in `nuxt.config.ts` under `croutonAuth.methods.oauth` (`github` / `google`, each with a `clientId` and `clientSecret`, usually read from `.env`).

### Check it

```bash
npx crouton --help
```

If a later `crouton generate` stops with **Missing Required Dependencies** even though the package is installed, the package is not in `extends` in `nuxt.config.ts` — the generator checks both.

## Add optional packages

Auth, admin and translations come with core. Everything else is a separate package, added with `crouton add`:

```bash
npx crouton add --list            # what is available
npx crouton add editor            # one package
npx crouton add editor assets     # several
npx crouton add maps --dry-run    # show the steps, change nothing
```

For each package, `crouton add`:

1. installs it with your package manager (skip with `--skip-install`)
2. adds it to `extends` in `nuxt.config.ts`
3. prints the same note for every package: `crouton add` does not create database tables, and if the package brings tables, the migration commands to run next (see the end of this section)

Then restart the dev server. `--force` reinstalls a package that is already there.

Some packages you can add: `editor` (rich text), `assets` (file uploads, media library), `maps`, `bookings`, `calendar`, `charts`, `pages` (CMS pages), `email`, `events` (change history), `collab` (live editing), `ai`, `themes`. `crouton add --list` reads the current list from the packages themselves.

::callout{icon="i-lucide-lightbulb"}
**Which packages an app uses is decided by `extends`** in `nuxt.config.ts`. The `features` key in `crouton.config.js` only holds answers to a package's setup questions for the generator; it does not switch a package on.
::

### Adding a package by hand

The same steps without the CLI:

```bash
pnpm add @fyit/crouton-bookings
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@fyit/crouton-core', '@fyit/crouton-bookings'],
  hub: { db: 'sqlite' }
})
```

For a package that has its own database tables, generate the migration:

```bash
pnpm db:generate        # an app made by crouton init (drizzle-kit, no Nuxt build)
npx nuxt db generate    # any other NuxtHub app
```

If the app's API calls return **500** right after adding a package, its tables were never created — the migration step was skipped.
