This page takes an app from [Installation](/getting-started/installation) to a working **products** screen in a layer called **shop**.

## 1. Write the field list

One JSON file per collection. Each key is a field name; `type` is required, `meta` is optional.

```json [schemas/products.json]
{
  "name": { "type": "string", "meta": { "required": true, "maxLength": 200 } },
  "description": { "type": "text" },
  "price": { "type": "decimal", "meta": { "precision": 10, "scale": 2 } },
  "inStock": { "type": "boolean", "meta": { "default": true } }
}
```

Do not add `id`, `teamId`, `owner`, `createdAt`, `updatedAt`, `createdBy` or `updatedBy` — every collection gets those automatically. The generator stops on an unknown type or an unknown `meta` key and names the field, so a typo never becomes broken code.

All field types: [Field types](/api-reference/field-types). The full file format, including links between collections (`refTarget`): [Schema format](/generation/schema-format).

## 2. Register it in `crouton.config.js`

```js [crouton.config.js]
export default {
  collections: [
    { name: 'products', fieldsFile: './schemas/products.json' }
  ],
  targets: [
    { layer: 'shop', collections: ['products'] }
  ],
  dialect: 'sqlite'
}
```

`collections` says where each field list is; `targets` says which layer each collection goes into. One layer can hold many collections.

## 3. Generate

```bash
npx crouton config
```

`npx crouton config --dry-run` shows the plan without writing. With no arguments, `npx crouton generate` finds `crouton.config.js` in the current folder and does the same. (You can also skip the config file for a one-off: `npx crouton generate shop products --fields-file ./schemas/products.json`.)

The run writes the collection into `layers/shop/collections/products/`:

```
layers/shop/collections/products/
├── app/
│   ├── components/
│   │   ├── _Form.vue              # registers as <ShopProductsForm>
│   │   └── List.vue               # registers as <ShopProductsList>
│   └── composables/
│       └── useShopProducts.ts     # validation (Zod), columns, defaults
├── server/
│   ├── api/teams/[id]/shop-products/
│   │   ├── index.get.ts           # list
│   │   ├── index.post.ts          # create
│   │   ├── [productId].patch.ts   # update
│   │   └── [productId].delete.ts  # delete
│   └── database/
│       ├── schema.ts              # Drizzle table shop_products
│       └── queries.ts
├── seed.json                      # sample rows you can edit
├── types.ts
├── nuxt.config.ts
└── README.md
```

It also wires the collection into the app, so there is nothing to register by hand:

- `./layers/shop` is added to `extends` in `nuxt.config.ts`
- `shopProducts` is added to `croutonCollections` in `app/app.config.ts`
- the table is exported from the app's database schema
- a migration for the new table is written to `server/db/migrations/`
- the Tailwind `@source` line is added to your CSS if it was missing

If the run prints **Migration deferred**, or stops at *Running database migration* with **Cannot find module '@fyit/…'**, the app's packages are not installed yet. The collection files are already written: run `pnpm install`, then `pnpm db:generate`.

## 4. Open it

```bash
pnpm dev
```

Sign up, create a team when asked, and open:

```
http://localhost:3000/admin/<your-team-slug>/crouton/shopProducts
```

You get the list with a create button. Create and edit open the generated form in a slide-over panel, and delete asks for confirmation; the list refreshes after each save. The migration was applied when the dev server started, and the rows belong to your team.

The last part of that URL is the collection's key in `croutonCollections` — layer + collection name in camelCase (`shop` + `products` → `shopProducts`).

## 5. Make it yours

- **Change a field:** edit `schemas/products.json` and run `npx crouton config --force`. Without `--force` the generator keeps every file that already exists, so the change does not show up. With it, every generated file of the collection is rewritten, including `seed.json` and any edits you made. See [Regenerating](/fundamentals/generated-code#regenerating).
- **Change the form or list for good:** create `app/components/ShopProductsForm.vue` (or `ShopProductsList.vue`) in your app. Your file wins over the generated one, and regenerating does not touch it. See [Eject](/customization/eject).
- **Remove the collection:** `npx crouton rollback shop products --dry-run` shows what goes, then run it without `--dry-run`. It removes the files and the config entries but not the database table — add `--drop-table` for a migration that drops it.
