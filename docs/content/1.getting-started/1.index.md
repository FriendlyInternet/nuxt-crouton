**Nuxt Crouton** turns a JSON list of fields into a working CRUD screen — form, list, API, database table and TypeScript types — inside a **[Nuxt](https://nuxt.com) 4** app. It has two halves:

- **The generator** (`@fyit/crouton-cli`, command `crouton`) writes code into your project. That code is yours.
- **The core layer** (`@fyit/crouton-core`) is a Nuxt layer your app extends. It holds the shared parts the generated code uses — the form modal, the table, data fetching, auth, teams — and is updated as a package.

## Generate → customize → own

You run the generator once per collection. It writes plain Vue, TypeScript and Drizzle files into `layers/<layer>/collections/<collection>/`. From then on they are ordinary files in your repo: read them, change them, commit them.

::callout{icon="i-lucide-triangle-alert" color="amber"}
**Regenerating keeps existing files.** Running the generator again for the same collection skips every file that already exists, so your edits survive, but a changed field list does not reach them either. `--force` rewrites them all, your edits included. To change a generated form or list for good, put your own component with the same name in your app's `app/components/` (your app's file wins over the layer's). See [Generated code](/fundamentals/generated-code#regenerating) and [Eject](/customization/eject).
::

## What one collection gives you

For a collection `products` in a layer `shop`:

| You get | Name |
| --- | --- |
| Create / edit / delete form | `ShopProductsForm` (file `_Form.vue`) |
| List (table) | `ShopProductsList` |
| Validation, columns, defaults | composable `useShopProducts` |
| API routes | `/api/teams/[id]/shop-products` (list, create, update, delete) |
| Database table | `shop_products` (Drizzle schema + a migration) |
| A screen in the admin area | `/admin/<team>/crouton/shopProducts` |

Every row belongs to a team: each collection gets a `teamId` column, and its API routes only return the signed-in user's team's rows.

## What the core layer includes

Extending `@fyit/crouton-core` also brings in, with no extra install:

- **Auth** (`@fyit/crouton-auth`) — [Better Auth](https://www.better-auth.com) with teams, sign-in pages, OAuth and passkeys
- **Admin** (`@fyit/crouton-admin`) — a super-admin area for users and teams
- **Translations** (`@fyit/crouton-i18n`) — multi-language fields and UI strings
- **[NuxtHub](https://hub.nuxt.com)** for the database, KV and file storage, **[Nuxt UI](https://ui.nuxt.com)** 4, **[Drizzle ORM](https://orm.drizzle.team)**, VueUse, Nuxt Image and Nuxt SEO

The app shell (`app.vue`) also comes from core, and it already mounts the form modal, so generated forms open without any setup.

Other packages — rich text, file uploads, maps, bookings and more — are optional; see [Installation](/getting-started/installation#add-optional-packages).

## What it is not

- **Not a runtime admin panel** like Strapi or Directus. There is no database-driven UI builder; the screens are generated source files.
- **Not a framework that hides your code.** The generated files live in your repo; the core layer is a normal Nuxt layer you can read.
- **Not for Nuxt 3.** It relies on Nuxt 4's `app/` folder layout for layers.
