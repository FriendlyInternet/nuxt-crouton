## Hypothesis
**We think that** every package should declare exactly the app's locales, **so that** no language appears that the app didn't configure. **We'll know by** no `nl` in the switcher, hreflang or URLs of an en/fr/es/it app.

## 👤 What this is about
crouton-assets hardcodes en/nl/fr, which adds Dutch to every app using the media library (switcher, hreflang, `/nl/` serving the English page). crouton-bookings, -catalog, -calendar, -events, -flow and -three do the same.

## Related
- #4375 (languages outside en/nl/fr crash the app) — same helper.

## 🧪 What the prototype did — assume it is wrong or unclean
A local, unpushed prototype (a four-language course site in `pocs/`) proved this need with quick spike code. Treat the following as a **sketch to challenge**, not an implementation to copy:

- crouton-assets switched to the `getLayerLocales` helper from #4375, imported by **relative path** (`../crouton-i18n/config-utils`) to avoid adding a dependency.
- **Likely problems:** relative cross-package import; the other six packages untouched.

## ✅ Done when
